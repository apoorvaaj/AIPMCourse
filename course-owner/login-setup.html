Sign-in setup guide

Connect the course sign-in page to a real email-code service

The sign-in page uses Supabase, a hosted backend service, for passwordless sign-in by email code. Until you add your project details, the page runs in preview mode: no email is sent and the code 123456 works.

1. Set up the service

  1. Create a Supabase project. Choose the Singapore region if it is offered, so learners' data stays close to them. Keep the database password somewhere safe; the course does not use it.
  2. Turn on email sign-in. In Authentication, then Sign In / Providers, make sure Email is enabled.
  3. Send a code instead of a link. In Authentication, then Email Templates, open the Magic Link template. Supabase uses this template for email codes too. Replace its body with: 
    <h2>Your sign-in code</h2>
<p>Enter this code to sign in to the AI Product Management Programme:</p>
<p style="font-size:28px;letter-spacing:6px;font-weight:bold">{{ .Token }}</p>
<p>The code expires in 10 minutes and works once only.
If you did not ask for it, ignore this email.</p>
    Set the subject to Your course sign-in code.
  4. Shorten the code's life. In the email provider settings, set the email one-time password (OTP) expiry to 600 seconds (10 minutes). The default is one hour. This setting also applies to other email links Supabase sends.
  5. Use your own email sender before launch. Supabase's built-in email sender is meant for testing and is tightly limited. Connect an email delivery service through the custom SMTP (Simple Mail Transfer Protocol) settings, using an address on your own domain, so codes arrive reliably and do not land in spam.
  6. Set the site address. In Authentication, then URL Configuration, set the Site URL to where the course will live, for example its own subdomain linked from your main website.
  7. Connect the page. In Project Settings, then API, copy the Project URL and the anon (publishable) key into the CONFIG block near the bottom of login.html: 
    const CONFIG = {
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR-ANON-KEY',
  afterSignIn: './',
  resendSeconds: 60
};
    The anon key is designed to sit in public web pages. Never put the service role key in any page: it bypasses every protection.

2. What this does not do yet

The sign-in page identifies learners. On its own it does not stop someone reading course pages directly if they know the address, because pages on a static host such as GitHub Pages are open to anyone. Before launch, choose one of these:

  • Serve course pages from private storage. Put the pages in a private Supabase Storage bucket that only signed-in users can read. The site shell loads each page after sign-in.
  • Put the course behind an access gate. Host on Cloudflare Pages or Netlify and check the sign-in session at the server before any page is sent.

The same step will store quiz progress in a table protected by row-level security, so each learner can read and write only their own rows.

3. Personal data checklist

  • Store only email address and course progress. Do not add name or employer fields.
  • Publish the privacy notice before launch, and link it from the consent box on the sign-in page.
  • Give learners a way to request deletion, and delete both the user and their progress rows.
  • Record who has administrator access to the Supabase project, and turn on two-factor authentication for those administrator accounts.
